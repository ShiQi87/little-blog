express中添加sequelize

收收味2025-3-16NodeJS/expresssequelizeORMexpress

了解到了 ORM（对象关系衍射），一种用函数生成 sql 语句的技术

准备

创建新 express 项目

express ORMExpress
cd ORMExpress
pnpm i

安装 squelize

pnpm i -g sequelize-cli
pnpm i sequelize mysql2
sequelize init

安装后，根目录下会出现四个新的文件

文件或目录说明
config/config.js数据库连接配置
migrations迁移文件，对数据库的表修改时使用
model模型文件，表的数据增删改查使用
seeders种子文件，需要添加到数据表的测试数据放在这

修改配置文件

填上自己的数据库信息

//开发环境数据库连接配置

新建数据库模型

sequelize model:generate --name Article --attributes title:string,content:text

指令结束，目录下新增两个文件，模型文件和迁移文件

sequelize db:migrate

可以发现此时数据库里多出一张新表，这里就是迁移文件的作用

填充测试数据

sequelize seed:generate --name article

此时 seeders 下多出一个新的种子文件

接口 1：查询文章列表

我们可以自定义规则对数据进行排序

按照倒序查询的语句是ORDER BY 'id' DESC，在 articles 里添加

const conditoin = {
  order: [["id", "DESC"]], // 可以按照多个字段排序
};

const articles = await Article.findAll(conditoin);

此时再刷新浏览器可以发现数据按照 id 倒序排列了

之后添加 try catch，方便我们调试寻找错误来源

try {
  const conditoin = {
    order: [["id", "DESC"]], // 可以按照多个字段排序
  };

  const articles = await Article.findAll(conditoin);
  res.json({
    status: true,
    message: "查询文章列表成功",
    data: {
      articles,
    },
  });
} catch (err) {
  res.status(500).json({
    status: false,
    message: "查询文章列表失败",
    err: [err.message], // 可能有多个表单信息
  });
}

至此一个接口就算完成了，对比不用 sequelize 的接口，我们把连接数据库，查询数据库的任务全部交给了 sequelize，查询数据仍然是异步操作，可以用语法糖 async，await

接口 2：查询文章详情

有时候会需要查看单条数据的全部信息，此时可以用/:params来用 req.params 收集地址传入的参数

router.get("/:id", async (req, res) => {
  // id会被保存到req的params上
  try {
    const { id } = req.params;
    const article = await Article.findByPk(id);

    if (!article) {
      res.status(404).json({
        status: false,
        message: "查询文章内容没有",
      });
    }

    res.json({
      status: true,
      message: "查询文章内容成功",
      data: { article },
    });
  } catch (err) {
    res.status(500).json({
      status: false,
      message: "查询文章内容失败",
      err: [err.message],
    });
  }
});

封装会重复使用的方法

实现删，改，查这三个接口，我们都会先使用查来看要进行操作的文章存在吗，这是一段需要重复使用的代码，可以封装

// articles.js
const getArticle = async (req) => {
  const { id } = req.params;

  const article = await Article.findByPk(id);

  if (!article) {
    throw new NotFoundError(`ID: ${id}的文章没有找到`);
  }

  return article;
};

当我们接收用户发来的数据时，要严格遵循不相信用户的原则，所以会使用到白名单校验，在增加和修改接口会用到白名单用于过滤用户传来的不需要的或具有攻击性的参数，只接受自己需要的参数，这个校验也可以封装

// articles.js
const filterBody = (req) => {
  // 白名单过滤（强数据过滤）
  return {
    title: req.body.title,
    content: req.body.content,
  };
};

由于接下来的所欲接口都会出现请求成功和失败的情况，所以为了减少重复代码，提升代码复用性，我们对这两个情况要用到的代码进行一个封装

新建文件夹 utils 用于存放工具函数和类，在其下新建文件 response.js

对于查询结果不存在的情况，我们自定义一个新的错误类，NotFoundError

// response.js
class NotFoundError extends Error {
  constructor(message) {
    super(message);
    this.name = "NotFoundError"; // es6语法，只有super以后this才会被初始化，才能使用this
  }
}

// 请求成功
const success = (res, message, data = {}, code = 200) => {
  return res.status(code).json({
    status: true,
    message,
    data,
  });
};

const failure = (res, error) => {
  if (error.name === "SequelizeValidationError") {
    // 数据库校验表单不通过会出现的错误类型
    const errors = error.errors.map((e) => e.message);

    return res.status(400).json({
      status: false,
      message: "请求参数错误",
      errors,
    });
  }

  if (error.name === "NotFoundError") {
    return res.status(404).json({
      status: false,
      message: "资源不存在",
      errors: [error.message],
    });
  }

  return res.status(500).json({
    status: false,
    message: "服务器错误",
    errors: [error.message],
  });
};

module.exports = {
  NotFoundError,
  success,
  failure,
};

状态码小记

HTTP 状态码及使用场景 下面是 HTTP 状态码的分类及示例：

1xx：信息性状态码 100 Continue：客户端请求头已发送，服务器确认可以继续发送请求体。 101 Switching Protocols：服务器同意切换协议，例如从 HTTP/1.1 切换到 WebSocket。 2xx：成功状态码 200 OK：请求成功，通常用于 GET、POST、PUT、DELETE 等。 示例：用户信息更新成功，返回更新后的数据。

201 Created：成功创建资源，通常用于 POST 和某些 PUT 请求。 示例：创建一个新订单。

202 Accepted：请求已被接受，但尚未处理。多用于异步任务。 示例：上传大文件后，服务器后台异步处理。

204 No Content：请求成功但无返回内容，常用于 DELETE 或 PUT。 示例：删除用户数据成功。

3xx：重定向状态码 301 Moved Permanently：资源永久移动，浏览器会自动重定向。 示例：旧的 URL 被永久替换。

302 Found：临时重定向，通常用于用户未登录时跳转到登录页。 示例：未授权用户访问受保护资源时。

304 Not Modified：客户端有缓存数据，资源未修改。 示例：浏览器请求带有 If-Modified-Since，服务器发现资源未变。

4xx：客户端错误状态码 400 Bad Request：请求格式错误或参数不合法。 示例：提交表单缺少必填项。

401 Unauthorized：需要认证或认证失败。 示例：未提供 Token 或 Token 无效。

403 Forbidden：服务器理解请求但拒绝执行。 示例：普通用户尝试访问管理员页面。

404 Not Found：请求的资源不存在。 示例：访问不存在的 API 路径。

405 Method Not Allowed：请求方法不被允许。 示例：用 POST 请求访问只允许 GET 的接口。

409 Conflict：资源冲突。 示例：用户尝试创建已存在的用户名。

422 Unprocessable Entity：请求格式正确但无法处理。 示例：表单字段校验失败。

5xx：服务器错误状态码 500 Internal Server Error：服务器内部错误。 示例：后端代码异常或数据库崩溃。

502 Bad Gateway：服务器作为网关或代理时收到无效响应。 示例：Nginx 转发到后端服务失败。

503 Service Unavailable：服务器暂时无法处理请求。 示例：服务器超载或维护中。

504 Gateway Timeout：网关超时。 示例：后端处理超时导致网关等待失败。

✅ 总结：如何选择状态码 是否成功？

200：数据更新成功并返回数据。 201：新建资源。 204：更新成功但无需返回数据。 是否需要重定向？

301：永久重定向。 302：临时重定向。 是否有客户端错误？

400：参数错误。 401：需要登录。 403：无权限。 404：资源不存在。 是否有服务器错误？

500：代码异常。 503：服务器维护或压力过大。

接口 3：添加文章

为路径添加 post 路由，请求地址仍然是 admin/articles/,post 请求会携带数据体 body，里面存放新增文章的数据，对 body 的处理可以看上一节的白名单过滤封装

// articles.js
router.post("/", async (req, res) => {
  // 新增文章接口有安全隐患，会被sql注入攻击，要设置白名单过滤
  try {
    const article = await Article.create(filterBody(req));

    success(res, "文章创建成功", { article }, 201);
  } catch (error) {
    failure(res, error);
  }
});

接口 5：更新文章

更新文章使用 put 请求，通过/:params找到符合文章，之后用 body 中携带的数据更新文章

router.put("/:id", async (req, res) => {

      article,
    });

优化接口

早期编写的接口并未考虑代码复用问题，而且功能也不够完善，我们可以添加模糊搜索，分页，表单校验，使接口更加完善

添加模糊搜索和分页

首先要了解的一点是如何传参让服务器知道要分的页的当前页面和每页最大容纳信息

我们可以通过URL? x=params1&y=params2，这些数据会被存储在 req.query 中

分页的 sql 语句是LIMIT 0, 10 0是offset，10是pageSize

在condition中添加新的条件对 sql 语句进行补充

      limit: pageSize, // 每页限制 sql语句 LIMIT 0, 10 0是offset，10是pageSize
      offset: offset, // 起始页

之后要记得初始化数据

const query = req.query;

// 数据分页功能
const currentPage = Math.abs(Number(query.currentPage)) || 1;
const pageSize = Math.abs(Number(query.pageSize)) || 10;
const offset = (currentPage - 1) * pageSize;

查询使用的函数也要进行相应的修改，我们改成findCountAndAll()，可以获取查询到的数据总数和数据

若请求路径里也携带了 title。说明用户要进行查询，sql 的模糊查询使用LIKE语句，%代表对应的地方可以有别的语句

if (query.title) {
  conditoin.where = {
    title: {
      [Op.like]: `%${query.title}%`, // 中括号代表计算属性值，中括号中的变量会被解析为Op.like的值的字符串格式，es6语法，记得从sequelize引入Op
    },
  };
}

加上这两个功能之后的代码

router.get("/", async (req, res) => {
  // 添加路由信息
  try {
    const query = req.query;

    // 数据分页功能
    const currentPage = Math.abs(Number(query.currentPage)) || 1;
    const pageSize = Math.abs(Number(query.pageSize)) || 10;
    const offset = (currentPage - 1) * pageSize;

    const conditoin = {
      // 条件
      order: [["id", "DESC"]], // 可以按照多个字段排序
      limit: pageSize, // 每页限制 sql语句 LIMIT 0, 10 0是offset，10是pageSize
      offset: offset, // 起始页
    };

    if (query.title) {
      conditoin.where = {
        title: {
          [Op.like]: `%${query.title}%`,
        },
      };
    }

    const { count, rows } = await Article.findAndCountAll(conditoin); // count 是查询到的数据总数，rows是查询到的数据

    success(res, "查询文章列表成功", {
      articles: rows,
      pagination: {
        total: count,
        currentPage,
        pageSize,
      },
    });
  } catch (error) {
    failure(res, error);
  }
});

// admin/articles
const express = require("express");
const { Article } = require("../../models");
const { Op } = require("sequelize"); // 引入Op模糊查询
const { NotFoundError, success, failure } = require("../../utils/response");

const router = express.Router(); // 创建router实例

/*
 * 查询所有文章 填参数模糊查询
 * GET /admin/articles
 */

router.get("/", async (req, res) => {
  // 添加路由信息
  try {
    const query = req.query;

    // 数据分页功能
    const currentPage = Math.abs(Number(query.currentPage)) || 1;
    const pageSize = Math.abs(Number(query.pageSize)) || 10;
    const offset = (currentPage - 1) * pageSize;

    const conditoin = {
      // 条件
      order: [["id", "DESC"]], // 可以按照多个字段排序
      limit: pageSize, // 每页限制 sql语句 LIMIT 0, 10 0是offset，10是pageSize
      offset: offset, // 起始页
    };

    if (query.title) {
      conditoin.where = {
        title: {
          [Op.like]: `%${query.title}%`,
        },
      };
    }

    const { count, rows } = await Article.findAndCountAll(conditoin); // count 是查询到的数据总数，rows是查询到的数据

    success(res, "查询文章列表成功", {
      articles: rows,
      pagination: {
        total: count,
        currentPage,
        pageSize,
      },
    });
  } catch (error) {
    failure(res, error);
  }
});
