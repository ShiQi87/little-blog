JS事件循环

事件循环是前端面试时经常问到的东西，这里的事件是把js中的语句分为了两类，即同步任务,异步任务；

其中异步任务又分为两种，宏任务和微任务。比如一整个js文件，它本身作为最大的一个代码块，就是一个宏任务，宏任务是由浏览器或者nodejs环境触发的任务，还包括两种定时器，setTimeout、setInterval;微任务则是JS引擎触发的任务，如Promise（promise中包含的一般语句也是同步任务，确切来说，promise作为异步任务的部分是Promise.then()）、process.nextTick()（顺带一提，后者的优先级要高于前者）；

事件循环的主要流程则如下:

  1. js的解释器按照顺序执行js代码，遇到同步任务直接执行，而遇到异步任务则按照类别将其放入宏任务或微任务队列当中；
  2. 当当前遇到的所有同步任务执行完毕（异步任务中可能还有同步任务，但是运行时并未进入异步任务代码块，所以暂且不管），开始执行异步任务中的微任务，微任务中如果存在同步任务就直接执行，异步任务则继续放入异步任务队尾；
  3. 当前所有微任务执行完毕，开始执行宏任务，遇到新的任务继续上一步的方式处理（同步任务执行，异步任务入队列尾部），每执行一个宏任务，检查微任务队列，有微任务则逐个执行，清空微任务队列，没有则执行下一个宏任务；

考虑到一整个js文件是最大的宏任务，实际上事件循环中循环进行的是执行一个宏任务，清空微任务队列，直至所有任务执行完毕

举例说明

setTimeout(function () {
    console.log(1) // 5.微任务执行完毕，执行宏任务，宏任务中没有其他异步任务，执行结束
}, 0);

new Promise(function (resolve, reject) {
    console.log(2); // 1.Promise中的同步代码直接执行，首先输出 2
    resolve();
}).then(function () {
    console.log(3) // 3.微任务队列，第三个输出输出3，执行结束把之后的.then加入微任务
}).then(function () {
    console.log(4) // 4.微任务队列没有清空，输出4
});

console.log(6); // 2.同步任务，直接执行，第二个输出6
// 2, 6, 3, 4, 1
